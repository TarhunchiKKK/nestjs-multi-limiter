# Failure Handling

Let's walk through how this library handles Redis failure.

## Failing Strategies

This library supports 3 strategies for Redis failure:

1. `fail-open` (default) - When Redis error occurs library allows all requests (recommended in high-load systems).  
2. `fail-close` - When Redis error occurs library rejects all requests (recommended for critical API's). 
3. `fail-fast` - When Redis error occurs library throws error immediately (recommended in staging environments).

## Configuration 

Here is an example of failing strategy configuration:

```typescript title="app.module.ts"
RateLimiterModule.forRoot({
    storage: {
        type: "redis",
        adapter: MyRedisAdapter,
        failingStrategy: "fail-fast" // or use another failing strategy
    }
})
```

## Adapter implementation

This library implements `Error Translation` (`Error Mapping`) pattern for Redis failure handling. It means, that if Redis is not available adapter should throw `RedisAdapterError` on every `eval` method call during Redis is not available. This error signals that Redis was failed and corresponding failing strategy will be applied.

```typescript title="redis.service.ts"
import  { type IRedisAdapter, type Key, RedisAdapterError } from "nestjs-multi-limiter";

@Injectable()
export class RedisService implements IRedisAdapter {
    private readonly client: Redis;
    private redisAvailable = true;

    public constructor(private readonly configService: ConfigService) {
        this.client = new Redis(/* ... */);
        this.client.on("error", () => {
            this.redisAvailable = false;
        })
    }

    public async eval(script: string | Buffer, numKeys: number, ...args: (number | string | Buffer)[]) {
        if (!this.redisAvailable) {
            // signals that redis is not available
            throw new RedisAdapterError();
        }
    
        return await this.client.eval(script, numKeys, ...args);
    }
}
```

## Subscribe on errors

`RedisAdapterError` instances will be handled by library. But if some another error occurs during Redis requests you also can subscribe on it. Such errors will always be thrown.

To subscribe on Redis errors via rate limiting (for example, for logging) you can implement optional `handleError` property of `IRedisAdapter` type:

```typescript title="redis.service.ts"
import type { IRedisAdapter, Key } from "nestjs-multi-limiter";

@Injectable()
export class RedisService implements IRedisAdapter {
    public constructor(private readonly loggerService: LoggerService) { }

    // ...
    
    public async handleError(error: unknown, key: Key) {
        this.loggerService.warn(`Redis disconnected for "${key}" key with error: ${error}`);
    }
}
```

Now when error occurs via rate limiting this method will be called with original error and computed rate limiting key.
